In the previous article we saw the basics of window functions: how `OVER()` lets you compute aggregated values without collapsing the result rows. Now let's dig into one of the most useful features within that `OVER()`: the `PARTITION BY` clause, which splits the table into groups before applying the function.

## `PARTITION BY`

When `PARTITION BY` is used with `OVER()`, SQL looks at each row of the table, one at a time. For each one, it figures out which group (partition) it belongs to, according to the `PARTITION BY`. Then it computes the function using only the rows in that group, not the whole table. The difference from a `GROUP BY` is that **the rows aren't collapsed**. Each row still shows up in the result, but it gains a column with a value computed from its group.

The query below compares each employee's salary with the average salary of their respective department:

```sql
SELECT depname,
	   empno,
	   salary,
	   AVG(salary) OVER (PARTITION BY dep_name) 
FROM empsalary;
```

The result shows the employees split by partition. The first three columns come from the `empsalary` table. The `avg` column is generated by the window function, which returns the average salary of each partition.
